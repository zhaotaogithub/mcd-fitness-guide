# 计算规则与示例

## 一、热量预算怎么来

### 1. 用户在减脂期，且知道自己今天的剩余额度
直接用。这是最准的输入。

### 2. 用户不知道，需要估算

```
每日总消耗（TDEE，久坐人群粗估）
  = 体重(kg) × 30 kcal          # 轻活动
  = 体重(kg) × 33 kcal          # 中活动
  = 体重(kg) × 36 kcal          # 高活动

减脂期每日摄入 = TDEE × 0.8    # 温和缺口约 20%
```

三餐分配（按热量占比）：

| 餐次 | 占比 |
|---|---|
| 早餐 | 30% |
| 午餐 | 40% |
| 晚餐 | 30% |

**示例**：70kg、久坐、减脂期

```
TDEE   = 70 × 30 = 2100 kcal
日摄入 = 2100 × 0.8 = 1680 kcal
午餐   = 1680 × 0.4 = 672 kcal
```

> **必须把估算过程写进输出**，并请用户校正。不要假装这是精确值。

### 3. 极端区间保护

单餐预算 **< 400 kcal** 时，脚本会打警告。此时不要在结果里硬凑一份「最低卡组合」，
应当建议：拆成两餐、或适当上调预算、或补充低卡的场外食物（水煮蛋、无糖酸奶）。

## 二、蛋白质目标

```
每餐蛋白质目标 = 体重(kg) × 1.6 g ÷ 3 餐
```

**示例**：70kg → 每日 112g → 每餐约 **37g**。

麦当劳的蛋白质主要来自牛肉饼、鸡胸/鸡腿肉、蛋、奶。一份汉堡通常 15–27g。
因此**单靠一份汉堡很难达到 30g 以上**，需要：
- 选双层/加蛋的主餐（如「原味板烧鸡腿炒双蛋堡」27g、「双层吉素汉堡」27g）
- 或搭配脆汁鸡、麦乐鸡等纯肉配餐

## 三、排序权重（`pick_meals.py` 内部）

### 主餐评分

```
基础分 = 蛋白质密度(每100kcal蛋白质克数) × 12
       + min(蛋白质克数, 目标) × 0.55
       + 热量贴近度奖励（占预算 50%~100% 时 +8）
       - 超标惩罚（超出预算部分 × 60）
       - 钠惩罚（>1000mg 后每 100mg 扣 1）
       - 脂肪惩罚（>25g 后每克扣 0.4）
       - 糖分刺客重罚（-40）
```

### 配餐评分

```
≤60 kcal  → +10        （几乎无代价）
≤180 kcal → +4
>180 kcal → 每超 60 kcal 扣 1
蛋白质 × 0.3
糖分刺客 → -30
```

### 组合加成

```
+ min(组合总蛋白质, 目标) × 0.4
+ 有饮品        → +5
+ 有固体配餐    → +4
「放开」档且热量 < 预算75% → -12
```

### 组合约束

- 结构：1 主餐 + 0~2 配餐
- 第二份配餐热量上限 160 kcal
- **同族饮料不重复**（不会出现「大杯咖啡 + 小杯咖啡」）
- 同类别配餐不重复两份（不会出现两份薯条）

---

## 四、三档方案的含义

| 档位 | 预算占比 | 定位 |
|---|---|---|
| 保守 | 70% | 宁少勿多，留给当天机动空间 |
| 标准 | 90% | 热量与饱腹感平衡，**通常推荐这档** |
| 放开 | 100% | 用满预算，吃得更满足 |

> 当预算本身较紧（如 550 kcal）时，三档可能收敛到同一方案——这说明
> 在这份菜单里 550 kcal 没有更好的填法。**如实告知，不要硬造差异。**

## 五、完整示例

### 输入

```
预算：550 kcal
蛋白质目标：30 g
数据：nutrition.json（158 条，来自 list-nutrition-foods）
```

### 命令

```bash
python scripts/pick_meals.py --budget 550 --protein 30 --data nutrition.json
```

### 输出（实测）

```
【保守方案】宁少勿多，优先控热量
  · 双层原味板烧鸡腿麦满分   355 kcal  蛋白 23g  钠  984mg  [主餐]
  · 大杯鲜萃咖啡             13 kcal  蛋白  1g  钠    3mg  [饮料]
  · 冰美式中杯               13 kcal  蛋白  1g  钠    0mg  [配餐]
  合计：381 kcal (69% 预算) | 蛋白质 25g | 脂肪 17g | 钠 987mg
  蛋白质达成度：83%

【标准方案】热量与饱腹感平衡
  · 原味板烧鸡腿炒双蛋堡     419 kcal  蛋白 27g  钠  715mg  [主餐]
  · 小杯玉米杯               53 kcal  蛋白  2g  钠    1mg  [配餐]
  · 大杯鲜萃咖啡             13 kcal  蛋白  1g  钠    3mg  [饮料]
  合计：485 kcal (88% 预算) | 蛋白质 30g | 脂肪 22g | 钠 719mg
  蛋白质达成度：100%
```

### 解读

- 标准方案达 88% 预算、蛋白质 100% 达成、钠仅 719mg —— 三个人体指标同时达标，
  这是**推荐方案**。
- 保守方案多一份咖啡，热量只降 100 kcal，性价比一般。
- 在 550 kcal 下没有更好的「放开」方案，说明该菜单的低卡区已到极限。

## 七、脚本参数速查

### nutrition_parse.py

```bash
python scripts/nutrition_parse.py <原始返回文件> -o nutrition.json
cat raw.txt | python scripts/nutrition_parse.py - -o nutrition.json
```

### pick_meals.py

```bash
python scripts/pick_meals.py --budget 550 --protein 30 --data nutrition.json
python scripts/pick_meals.py --budget 550 --data nutrition.json --json
python scripts/pick_meals.py --budget 600 --avoid "新地,麦旋风,派" --data nutrition.json
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--budget` | 必填 | 本餐热量预算 kcal |
| `--protein` | 30 | 蛋白质目标 g |
| `--data` | nutrition.json | 营养数据路径 |
| `--avoid` | 空 | 忌口关键字，逗号分隔 |
| `--json` | 关 | 输出 JSON |

**退出码**：0 正常；1 输入异常；2 无可行方案
